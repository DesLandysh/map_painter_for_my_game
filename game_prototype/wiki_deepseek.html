Гексовый прилив

Изометрическая одиссея: маленькая лодка плывёт по «живому» морю, собранному из ~25 гексов в высоту в каждом тайле. Цель — собрать 8 искр. Мир реагирует на лодку (волны, след, рикошет от берегов), ветер сносит её и меняет погоду.

Порядок инициализации

  1. renderer + scene + camera (ортографическая).
  2. Свет: Hemisphere + sun (Directional, тени) + два fill'а.
  3. Текстуры: glow, foam (радиальные градиенты).
  4. Сетка тайлов, классификация (вода / суша / зона).
  5. addSlab — 4 подложки диорамы.
  6. createColumnGeometry (25 полос) → landMesh.
  7. createOceanColumnGeometry (1 полоса) → oceanMesh + шейдер.
  8. Декор: деревья (Instanced), камни (Instanced), пальмы, домики, маяк.
  9. Частицы, след (ribbon), лодка, искры.
  10. Звук по кнопке play, камера → fitCamera(), затем renderer.setAnimationLoop(animate).

Единицы измерения

  • 1 юнит ≈ 1 метр. HEX_R = 0.155 — радиус одного гекса.
  • Тайл = 5×5 гексов. TILE_W = 5·√3·R ≈ 1.34, TILE_D = 7.5·R = 1.1625.
  • Карта: NX = 100, NZ = 40 тайлов → MAP_W ≈ 134, MAP_D ≈ 46.5.
  • Скорость лодки: 0…5.1 (юнитов/сек). Камера: 0.9 (обзор) … 2.4 (крупный план).

Debug-режим

При открытии index.html?debug создаётся window.__hexDebug с методами advance(seconds) (шаг симуляции 1/60 без рендера) и ссылками на state, keys, camera, cameraRig, oceanUniforms. Удобно для тестов и профилирования.

Утилиты и формулы

Математические хелперы

clamp(v, a, b) → number

Ограничивает значение отрезком [a, b].

Math.max(a, Math.min(b, v))
lerp(a, b, t) → number

Линейная интерполяция. t — обычно 0…1.

a + (b - a) * t
smoothstep(a, b, x) → number ∈ [0, 1]

Кубическое сглаживание: даёт «мягкие» края без рывков.

t = clamp((x - a) / (b - a), 0, 1);
return t * t * (3 - 2 * t);
expDamp(current, target, lambda, dt) → number

Экспоненциальное сглаживание, независимое от FPS (frame-rate independent). λ — «жёсткость» (больше = быстрее догоняет).

current + (target - current) * (1 - Math.exp(-lambda * dt))
dampAngle(current, target, lambda, dt) → number

То же, но для углов. Учитывает переход через ±π (wrap на короткую дугу).

delta = atan2(sin(target - current), cos(target - current));
return current + delta * (1 - exp(-lambda * dt));

Генераторы случайности

mulberry32(seed) → () => number ∈ [0,1)

Детерминированный PRNG на 32-битных операциях. Используется для декора, чтобы внешний вид карты был стабильным при перезагрузке.

a = (a + 0x6D2B79F5) | 0;
t = Math.imul(a ^ (a >>> 15), 1 | a);
t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
hash2(x, z) → number ∈ [0,1)

Быстрый псевдо-хэш на синусе. Основа для value noise.

v = sin(x * 127.1 + z * 311.7) * 43758.5453123;
return v - floor(v);
valueNoise(x, z) → number ∈ [0,1)

Value-noise с bilinear-интерполяцией и smoothstep'ом. Даёт «облачную» карту высот и шума ветра.

xi = floor(x); zi = floor(z); xf = x-xi; zf = z-zi;
u = xf*xf*(3-2*xf); v = zf*zf*(3-2*zf);
a = hash2(xi, zi); b = hash2(xi+1, zi);
c = hash2(xi, zi+1); d = hash2(xi+1, zi+1);
return lerp(lerp(a,b,u), lerp(c,d,u), v);

Форматирование

formatTime(seconds) → "M:SS"

Для отображения таймера в финальном экране.

Генерация мира

Шаг 1 — сетка тайлов

Центр карты в (0, 0). Каждый тайл — 5×5 гексов. Координаты:

tileX(tx) = (tx - (NX-1)/2) * TILE_W
tileZ(tz) = (tz - (NZ-1)/2) * TILE_D
idxOf(tx, tz) = tz * NX + tx

Шаг 2 — острова (ISLANDS)

Массив ручных островов. У каждого: x, z (центр), r (базовый радиус), seed (смещение фазы шума), peak (0…1.2, высота), name. Пример: Юкатан, Куба, Гаити, Малые Антильские…

Форма берега (wobble)

Граница острова — не круг, а сумма синусов от полярного угла:

wobble(θ) = 1
          + 0.25·sin(3θ + seed)
          + 0.15·sin(5θ − 1.7·seed)
          + 0.08·sin(8θ + 1.4)
          + 0.05·sin(13θ + 2.3·seed)

edge = r · wobble(θ)
q    = dist / edge   // 0 = центр, 1 = берег

Тайл считается сушей, если dist < edge хотя бы у одного острова. Приоритет — минимальный q.

Шаг 3 — классификация тайлов

УсловиеzoneВысота (base)
q > 0.79sand0.30 + micro·0.14
0.56 < q ≤ 0.79grass0.54 + micro·0.17
0.39 < q ≤ 0.56hill0.84 + micro·0.29 + (0.56 − q)·0.7
q ≤ 0.39peak1.08 + micro·0.35

Плюс peakRise — плавный «вулкан» в центре острова:

peakRange = r · 0.5
peakT     = clamp(1 − dist/peakRange, 0, 1)
peakRise  = (3.15 + r·0.24) · peak · peakT1.62
height   += peakRise

micro — сумма двух value-noise: крупный (×0.58) + мелкий (×0.22).

Цветовые переходы

  • rockBlend = smoothstep(1.05, 3.1, peakRise) — выше 1.05 подмешивает rock→rockDark.
  • snowBlend = smoothstep(3.85, 4.75, height) · (0.68 + tint·0.28) — на вершинах.
  • tint = valueNoise(x·4.7 + 10.2, z·4.7 − 3.8) — стабильный «разброс» цвета.
  • Плюс HSL-смещение: offsetHSL((tint−0.5)·0.018, (tint−0.5)·0.04, (tint−0.5)·0.055).

Сглаживание краёв (falloff)

if (tile.edge && tile.q > 0.7) {
  blend = smoothstep(0.7, 1.0, tile.q);
  height    = lerp(height, 0.1, blend · 0.5);
  baseColor.lerp(palette.mid, blend · 0.3);
}

Без этого берег обрывался бы в море вертикальной «стеной».

Шаг 4 — гексовые колонки

В каждом тайле 5×5 гексов (25 колонок). Локальные координаты:

x = tileX(tx) + (col − 2)·HEX_SX + ((globalRow % 2) ? HEX_SX/2 : 0) − HEX_SX/4
z = tileZ(tz) + (row − 2)·HEX_SZ
где globalRow = tz·5 + row

Так столбики соседних тайлов сшиваются в непрерывную пчелиную соту — без швов.

Шаг 5 — меши

МешГеометрияИнстансы
oceanMesh1 призма на гекс (6 боковых + 6 верхних), без 25 полос — полосы рисуются в шейдере≈ 80 000+ (по числу водных гексов)
landMesh25 полос в высоту с вершинным цветом (bandLight 0.56…0.66)≈ 15 000 – 20 000
foundationMeshкуб на тайл, цвет = zone-цвет≈ 600 – 800

landMesh — полноценные 25 полос, чтобы переход по высоте читался «бахромой». Цвет полос чередуется: bandLight = 0.56 + (1 − b/bands)·0.075 + (b % 2 ? 0.025 : 0).

oceanMesh — упрощённая призма. Полосы и цвет верх/низ считаются прямо во фрагментном шейдере по vLocalH = clamp(-position.y, 0, 1).

Шаг 6 — декор

  • Деревья — на тайлах grass/hill с вероятностью ~58%/38% и avgHeight < 2.15. InstancedMesh: trunks, lowerCrowns, upperCrowns. Цвет кроны = palette.grass.lerp(palette.hillLight, 0.12…0.57).
  • Камни — InstancedMesh Dodecahedron с рандомным поворотом.
  • Пальмы — 4 шт. вручную, каждая = 3 сегмента ствола + 7 листьев-конусов + 3 кокоса. Не инстансится (мало штук).
  • Домики — 2 шт.: box-стены + конус-крыша + труба + дверь + окно (glow-панель).
  • Маяк — 1 шт.: 7 цилиндров + glow-sprite + конус-луч + PointLight. Луч вращается в основном цикле.

Шейдер океана

Реализован через MeshStandardMaterial.onBeforeCompile — это не отдельный ShaderMaterial, а патч стандартного материала Three.js.

Атрибуты на инстанс

  • aPhase — фаза волны (стабильный хэш от позиции).
  • aShade — затемнение от крупного/мелкого шума (0.94…1.05).

Вершинный шейдер — волновая формула

// проекция мировой позиции на направление ветра
alongWind   = dot(instXZ, (sin(windAngle), cos(windAngle)))
acrossWind  = dot(instXZ, (-cos(windAngle), sin(windAngle)))

// две синусоиды — фоновое волнение
ambient = sin(uTime·1.08 + alongWind·0.55 + aPhase)·0.09
        + sin(uTime·1.63 + acrossWind·0.22 + 0.9 + aPhase·0.31)·0.05

target = ambient

// влияние лодки (в радиусе √18 ≈ 4.24)
hull  = exp(-d² · 1.25)                       // −0.255
bow   = exp(-(d − 1.08)² · 4.54)              // +0.375
ring  = exp(-(d − 1.90)² · 1.92)              // +0.088
speedK = 0.58 + boatSpeed·0.12

target += -0.255 · hull · speedK
target += +0.375 · bow  · speedK · (0.68 + max(0,ahead)·0.38)
target += +0.088 · ring · speedK

// трейл
для i in trail[0..count):
  decay  = exp(-age·0.92) · strength
  ripple = sin(td·8.4 − age·7.2) · exp(-td·1.24)
  target += ripple · 0.208 · decay

// clamp + squash
wave    = clamp(target, -0.43, 0.6)
squash  = max(0, -wave)·0.3 + clamp(foam, 0, 0.75)·0.14
y      += wave / 2.1
xz     *= 1 + squash

Фрагментный шейдер — цвет

depthT = clamp((vWave + 0.18) / 0.42, 0, 1)
water  = mix(deep, mid,   smoothstep(0.0, 0.52, depthT))
water  = mix(water, crest, smoothstep(0.5, 1.0, depthT))
если vWave > 0.075 → подмешать foam (0.54)
если vFoam > 0.015 → подмешать foam (vFoam·0.88)

// полосы (banding) по vLocalH — 25 штук, «шов» через smoothstep
bandCoord = fract(vLocalH · 25)
bandEdge  = min(bandCoord, 1 - bandCoord)
seam      = mix(0.70, 1.0, smoothstep(0, 0.11, bandEdge))
bandTint  = mix(0.93, 1.015, mod(floor(vLocalH · 25), 2))
sideTone  = mix(seam·bandTint, 1.055, vTop)   // верх светлее

diffuseColor.rgb *= water · sideTone · vShade

Земля

MeshStandardMaterial({ vertexColors: true, roughness: 0.88, flatShading: true }) — цвет запекается в атрибут instanceColor при setColorAt. 25 полос в геометрии дают полосатость как у океана, но через атрибут color в вершинах.

Частицы (Points)

  • ShaderMaterial с текстурой пены.
  • gl_PointSize = clamp(aSize · uScale, 1, 64), где uScale = particleScaleBase · cameraRig.zoom.
  • particleScaleBase = (drawBuffer.y / viewH) · 1.45 — автоматически уменьшает частицы при отдалении.
  • Blending: Additive, depthWrite: false, toneMapped: false.

След (ribbon)

24 точки × 3 вершины. Каждая точка = {x, z, age, strength}. Строится каждые 55 мс при boatSpeed > 0.25, живёт до 3.1 с. Рендерится поверх воды (renderOrder = 3, additive).

fade  = (1 − age/3.15)^1.45 · strength
width = (0.075 + age·0.06) · (0.58 + speed/4.8)
y     = 0.45 + sin(age·2.1 + i)·0.007

Мотыльки / mote

52 точки, PointsMaterial с glow-текстурой. Каждая колеблется по sin/cos вокруг своей базовой позиции.

Лодка

Группа из ~15 мешей: hull (ExtrudeGeometry), topPlate, deck, планки, мачта, гик, парус (BufferGeometry с ручной триангуляцией), флаг, rope, бушприт, ящик, каюта, фонарь (стекло + glow), PointLight, контактная тень.

Иерархия: root (позиция + heading) → tilt (roll/pitch от скорости и поворотов) → меши.

Формула качки:

targetRoll  = clamp(-turnRate·0.045, -0.17, 0.17) + sin(t·1.13)·0.018
targetPitch = clamp(speed/5.1·0.09, 0, 0.09) + sin(t·1.47+0.4)·0.012
roll  = expDamp(currentRoll,  targetRoll,  4.5, dt)
pitch = expDamp(currentPitch, -targetPitch, 4.5, dt)

Искры

Icosahedron + Sprite(glow) + Torus. Плавное покачивание y = baseY + sin(t·1.45 + phase)·0.08. При сборе — collectT 0.42 с, group.scale растёт до 2.8, y уходит вверх, opacity затухает.

Игровая логика

Ввод

  • Клавиатура: KeyW/A/S/D, ArrowUp/Down/Left/Right, ShiftLeft/Right (boost), KeyR (reset).
  • Курс строится так: W даёт вектор «вперёд» (-1,-1)/√2, D — «вправо» (1,-1)/√2. То есть ввод мапится на изометрию.
  • Тач: mobilePad → те же keys[code], touch-action: none на кнопках.
  • На blur все клавиши сбрасываются.

Физика лодки (updateBoat)

// 1. Ввод → желаемый курс
dir = keyVectors.right·ix + keyVectors.forward·iz, normalize
targetHeading = atan2(dir.x, dir.y)
heading = dampAngle(heading, targetHeading, 6.2, dt)

// 2. Собственная скорость вдоль курса
boost ? 5.1 : 3.25
boatSpeed = expDamp(boatSpeed, targetSpeed, hasInput ? 3.2 : 2.0, dt)

// 3. Ветер сносит
windAtBoat = getWindAt(boat.x, boat.z)
driftVx = windAtBoat.x · wind.driftFactor   // 0.32
driftVz = windAtBoat.z · wind.driftFactor
selfVx  = sin(heading) · boatSpeed
selfVz  = cos(heading) · boatSpeed
desiredVx = selfVx + driftVx
desiredVz = selfVz + driftVz

// 4. Скорость с инерцией
vx = expDamp(vx, desiredVx, 3.8, dt)
vz = expDamp(vz, desiredVz, 3.8, dt)

// 5. Коллизия — отдельно по осям (slide along walls)
nextX = x + vx·dt; if (canSail(nextX, z)) x = nextX; else vx *= -0.15
nextZ = z + vz·dt; if (canSail(x, nextZ)) z = nextZ; else vz *= -0.15

Коллизия (canSail)

  • Проверка выхода за границы карты (margin 0.68).
  • Проверка 10 точек по окружности радиуса 0.67 вокруг лодки → isLandPoint.
  • Раздельно по осям — это даёт «скольжение» вдоль берега вместо застревания.
  • При ударе — emitCollisionFoam с кулдауном 170 мс (защита от флуда частиц).

Ветер (getWindAt / updateWind)

Локальная вариация

localOffset   = (valueNoise(x·0.035+7.1, z·0.035+3.3) − 0.5) · 2 · 0.45
localStrength = 0.75 + valueNoise(x·0.021+99, z·0.021+77) · 0.5
angle    = wind.angle + localOffset
strength = wind.strength · localStrength

Смена сезона

  • Каждые 40–80 с (счётчик seasonTimer).
  • targetAngle += (rand() − 0.5) · π · 0.9 — плавный поворот до ±45°.
  • targetStrength = 0.25 + rand() · 0.65.
  • Приближение: angle += delta · (1 − exp(−0.09·dt)) — очень мягкое.
  • Порывы: gustTimer = 4…12 с; на 1.5 с сила подскакивает до min(1, strength · (1.3…1.7)).

Проекция на экран (updateWindIndicator)

windVec3D = (getWindAt.x, 0, getWindAt.z)
screenVec = windVec3D.clone().project(camera)
angleRad  = atan2(screenVec.x, -screenVec.y)
deg       = angleRad·180/π + 90      // +90 — калибровка под изометрию
deg       = ((deg % 360) + 360) % 360
windArrowEl.setAttribute('transform', `rotate(${deg} 24 24)`)

+90° — потому что project() даёт Y вверх, а SVG — Y вниз; плюс поворот камеры. Калибровка подобрана на глаз.

След и пена

  • Трейл пишется каждые 55 мс, точки живут до 3.1 с. Хранится в state.trail, обрезается до wakeMax.
  • Ribbon (24 точки × 3 вершины) — геометрический след, лежит на воде.
  • Частицы — emitWakeParticles: спавн с вероятностью boatSpeed/4.8, скорость зависит от boatSpeed.
  • Коллизионная пена — 7 частиц с кулдауном 170 мс + navigator.vibrate(8) на мобилке.

dx = boat.x − c.x; dz = boat.z − c.z;
if (dx² + dz² < 1.32²) collect(c)

Радиус 1.32 = 8.5 радиусов гекса — комфортный «магнит». После 8-й искры state.finished = true, через 1.2 с — end-screen.

Камера (updateCamera)

speedT     = smoothstep(0.04, 4.2, boatSpeed)
targetZoom = lerp(2.4, 0.9, speedT)
zoom       = expDamp(zoom, targetZoom, 1.75, dt)

lead       = 0.18
boatFocus  = (boat.x + vx·lead, 0.55, boat.z + vz·lead)
cameraFocus.lerp(boatFocus, 1 − exp(−3.25·dt))

«Скорость → отъезд» даёт кинематографичный эффект: на стоянке лодка крупная, на ходу — обзор шире.

Звук (Sound)

  • Шум океана: буфер 4 с белого шума → one-pole lowpass (α = 0.015), фильтр lowpass 540 Гц, Q = 0.65, gain 0.13.
  • LFO 0.082 Гц, ±0.052 — «дыхание» прибоя.
  • Дрон: 98 / 147 / 196 Гц sine.
  • Chime: 523.25 / 659.25 / 783.99 / 1046.5 Гц, две гармоники (sine + triangle на 1.5×), 1.8 с затухание.
  • Finish: арпеджио по 0.11 с.
  • Мастер-гейн 0.6. setMuted плавно гасит за 0.4 с.

Оптимизация

Ниже — список улучшений, которые имеет смысл рассмотреть. Каждое помечено уровнем влияния: critical — заметно на слабом железе, major — потенциальный FPS/память, minor — качество / чистота.

1. Меши и инстансинг

1.1. Лодка: объединить меши в единый BufferGeometry

Сейчас createBoat() создаёт ~15 отдельных Mesh + PointLight + Sprite. Все статические части (hull, deck, планки, мачта, гик, бушприт, ящик, каюта, верёвки, флаг-основа) можно:

  • склеить в одну геометрию с несколькими material-groups (по цвету), либо
  • собрать в одну GLTF/GLB модель (three/examples/jsm/loaders/GLTFLoader) — грузится 1 раз, не пересоздаётся.

Даст: 15 draw calls → 1–2, плюс меньше работы Matrix4.updateMatrixWorld каждый кадр. Для одной лодки эффект невелик, но при нескольких (если захочется) — критично.

major · draw calls & CPU

1.2. Пальмы → InstancedMesh

4 пальмы × 13 мешей = 52 объекта в сцене, и каждый — свой MeshStandardMaterial. Варианты:

  • Склеить каждую пальму в 1 геометрию (3 материала → 3 группы) — 4 меша.
  • InstancedMesh стволов + листьев + кокосов — 3 меша на всё.
  • Меньше всего кода — вынести createPalm в общую «фабрику» и мержить через BufferGeometryUtils.mergeGeometries.

major · 52 → 3–4 draw calls

1.3. Домики и маяк — статика, но пересоздаются

Домиков 2, маяк 1. Каждый домик — 6 мешей + glow; маяк — 8 мешей + Sprite + конус-луч + PointLight. Итого ~25 draw calls на 3 объекта. Проблема — каждый MeshStandardMaterial создаётся заново на каждый вызов createCottage(), что плодит текстуры/shader program.

  • Сделать общие материалы для домиков (wall / roof / wood) — переиспользовать.
  • Склеить геометрию каждого домика в один меш с группами.
  • Маяк — 1 GLB или merged BufferGeometry.

major · ~25 → ~6 draw calls

1.4. Деревья и камни — уже InstancedMesh ok

Молодцы, что сделано сразу. Единственное — frustumCulled = false. Для инстансов это правильно, потому что иначе они «пропадают», но можно вручную вычислять bounding sphere и включать frustumCulled = true, если зоны чётко разделены.

minor · 0.5–1 ms на слабых картах

2. Гексовые столбики

2.1. Заменить 25 реальных полос в landMesh на «полосатость в шейдере»

Сейчас суша — 25 отдельных полос в геометрии (25 × 12 вершин × 6 граней). Аналогично воде, где полосы рисуются во фрагментном шейдере. Логично унифицировать: суша тоже становится лёгкой призмой, а vLocalH + seam + bandTint берут на себя всю «полосатость». Но у суши сейчас flatShading: true и цвет вершин — при переносе в шейдер нужно будет передавать instanceColor как атрибут, что уже делается через setColorAt.

Это уменьшит геометрию в ~25 раз для суши и, что важнее, откроет дорогу к склейке дальних тайлов.

critical · 25× меньше памяти + быстрее shadow pass

2.2. Заменить гексовые столбики на «плоскую землю с hex-текстурой»

Радикальный вариант: один тайл = один плоский quad с текстурой (hex grid) + normal map + vertex displacement в шейдере. Это убьёт 100 000 инстансов и заменит их ~4 000.

Что потеряется:

  • Настоящая 3D-столбчатость — её видно на закате, когда столбики дают «бахрому».
  • Реальная глубина (дно) — придётся имитировать нормалями.
  • Тени от столбиков друг на друга.

Что выиграется: колоссально (в 20–30 раз) меньше геометрии; шейдер один, в него можно засунуть хоть 100 уровней полосатости.

Компромисс: гибрид — ближние 20–30 тайлов рендерить настоящими столбиками, дальние — плоскими quad'ами с той же текстурой. Как раз LOD-подход.

critical · до 10× быстрее на мобилках

2.3. LOD для столбиков

Если гибрид — слишком много работы: сделать 2–3 уровня детализации столбиков (25 / 9 / 3 полосы) и переключать по расстоянию до cameraFocus. Или вообще отключать полосы дальше 30 юнитов.

major · +30–50% FPS в 100×40

2.4. Дальние тайлы — merge в один InstancedMesh

Вместо 25 отдельных инстансов на тайл — один инстанс на дальний тайл (просто куб/призма). Меняется per-tile. Даёт −90% инстансов вдали.

major · критично для 100×40

3. Шейдер океана

3.1. Ранний выход для далёких инстансов

В вершинном шейдере for (i = 0; i < 12; i++) по трейлу всегда выполняется. Можно передать uniform float uTrailActive и на дальних тайлах (например distance > 20) пропускать цикл. Даст −5–15% vertex time.

major · vertex shader

3.2. Уменьшить OCEAN_TRAIL_SAMPLES с 12 до 6–8

12 циклов на 80 000 инстансов — это 960 000 итераций в кадр. Визуально трейл после 8 уже не читается. 8 или 6 — достаточный компромисс.

major · −25% vertex time

3.3. flatShading: true для воды → varying vFoam/vShade можно считать через fwidth

Сейчас шейдер считает всё линейно, flat shading — уже есть. Особой выгоды от смены нет, но можно попробовать убрать banding и брать fwidth(vLocalH) вместо явного fract(vLocalH * 25) — читаемость лучше, цена та же.

minor · чистота кода

3.4. «Заморозить» шейдер, если лодка стоит

Если boatSpeed < 0.05 и трейл пуст, и wind.strength не менялся 200 мс — можно пропускать обновление uBoat и uTime (но шейдер всё равно считается). Скорее экономия на GPU-латентности, чем на FPS. Идея спорная, но имеет смысл на паузе.

minor

3.5. Сравнить с одним ShaderMaterial вместо onBeforeCompile

MeshStandardMaterial тянет за собой весь освещённый пайплайн. Для воды часто достаточно MeshBasicMaterial + ручной фейк-освещение по нормали → −30% фрагментных вычислений. Но потеряется реакция на тени/свет, которая сейчас есть.

major · fragment shader

4. Тени

4.1. Обновлять shadow map не каждый кадр

renderer.shadowMap.autoUpdate = false + вручную вызывать needsUpdate = true только когда sun.position сдвинулся на > 0.5, или когда камера «перескочила» на новый тайл. Сейчас — каждый кадр, 2048×2048.

Это самое заметное улучшение после геометрии.

critical · 30–50% FPS

4.2. Уменьшить shadow map 2048 → 1024

На изометрии разница почти не видна. Экономит ~4× памяти и скорость записи.

major · −8 MB GPU + быстрее

4.3. Точечный свет маяка

PointLight(0xffbf70, 5.2, 7.5, 2) — один, но каждый PointLight = +1 shader pass во всех материалах в радиусе. Ладно бы 1 — но если захочется ещё, нужно переходить на fake emissive (всегда видимый glow sprite) вместо реального PointLight.

minor · сейчас

5. Процедурная карта / ручные тайлы

5.1. Оставить ручное размещение островов — правильно

Сейчас ISLANDS — массив объектов, каждый вручную задан. Это даёт контроль: можно расположить острова «как в реальном Карибском бассейне», подобрать ритм. Полностью процедурная генерация (Voronoi, Perlin-континенты) даст «ещё один процедурный мир» и не даст узнаваемых очертаний.

Плюс: ISLANDS — уже вынесены в конфиг, менять легко.

R&D, не производительность

5.2. Кэшировать сгенерированную карту

На каждом старте 100×40 тайлов проходят через двойной цикл + wobble, потом второй проход по всем landTiles, потом создание колонок. Для маленькой карты — быстро, но можно вынести в Web Worker или кэшировать в localStorage как JSON (позиция + тип + высота). При старте — только JSON.parse.

Даст: −50–150 мс на старте, что для «мгновенной загрузки» приятно.

major · startup time

5.3. Заменить «квадратные тайлы» на «гексагональные тайлы»

Сейчас каждый тайл — квадрат 5×5 гексов, но между квадратными тайлами гексы сшиваются вручную (см. globalRow % 2). Это работает, но при полном гекс-гриде (hex tiles 7×7, 19×19) можно было бы:

  • Один инстанс на гекс вместо 25 — но это уже сейчас так.
  • Убрать швы на границах тайлов (сейчас их нет визуально, но логически гексы привязаны к квадратной сетке).
  • Упростить frustum culling — bounding sphere гекса — реальная.

Но: (а) карта квадратная по логике (100×40), (б) «квадратный тайл» удобен для диорамы-подложки. Не факт, что стоит менять.

архитектурный выбор

6. Частицы и след

6.1. Пул частиц — уже есть ok

120 частиц, кольцевой буфер, particleCursor. Хорошо. Единственное — updateParticles проходит по всем 120, даже если 100 мертвы. Микрооптимизация: хранить aliveCount.

minor

6.2. Ribbon — ребилд только при изменении

updateWakeRibbon вызывается каждый кадр и перезаписывает все 24 × 3 вершины. Если state.boatSpeed < 0.05 и trail.length === 0 — можно return сразу. Микро, но в покое FPS подскочит.

minor · idle

7. Pixel ratio и рендер

7.1. Понизить getPixelRatio на мобильных

Сейчас min(dpr, 1.65) на мобильных, min(dpr, 2) на десктопе. На retina-мобиле 1.65 — это ~2.6M пикселей при 1080p экране. Разница между 1.65 и 1.2 — заметна только в статике. Уменьшит fill rate на 40%.

critical · мобильные

7.2. Отключить antialias на мобильных и включить FXAA-пост

MSAA в WebGL дорогой. Компромисс: на мобильных antialias: false, а на десктопе оставить. Или использовать SMAA из three/examples.

major · мобильные

8. Звук

8.1. Шум океана — буфер 4 с ok

Loop через source.loop = true — хорошо, не пересоздаётся.

ok

8.2. При смене таба вкладки — ctx.suspend()

Если пользователь ушёл с вкладки, звук продолжает играть. Можно document.visibilitychange → ctx.suspend() / ctx.resume().

DX

10. Итоговый «топ-5» для ближайшего спринта

  1. shadowMap.autoUpdate = false + ручной needsUpdate (30–50% FPS).
  2. Заменить 25-полосную геометрию суши на шейдерную, как у воды (25× меньше вершин).
  3. Понизить pixelRatio на мобильных до 1.2 и antialias: false (40% fill rate).
  4. Склеить лодку / пальмы / домики в объединённые геометрии (≤ 10 draw calls вместо 100+).
  5. Кэшировать сгенерированную карту в localStorage — мгновенный старт.

Мелкие баги, которые можно починить заодно

  • Стартовая позиция в state.boat (0, 2.5) не совпадает с resetGame (4.5, -1.8) — после R лодка «прыгает».
  • .hud-top в CSS — grid на 3 колонки, а детей 4 (brand / quest / wind-indicator / top-actions). top-actions уезжает во 2-ю строку.
  • Мобильный медиазапрос: .wind-indicator и .top-actions оба в col 2 row 1 — наезжают.
  • particleCount в spawnParticle: индексация через particleCursor - 1 с обёрткой — работает, но легко запутаться; лучше явно считать const idx = particleCursor.
  • Sound.setMuted — при muted = true gain становится 0, но новый звук всё равно спавнится; лучшe if (muted) return в chime/finish.
  • frustumCulled = false на частицах и следе — если они вне экрана, всё равно считаются. Для Points с 120 точками — мелочь, но можно убрать.
